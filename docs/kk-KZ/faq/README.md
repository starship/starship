# Жиі қойылатын сұрақтар (FAQ)

## Демо GIF-те қандай баптау қолданылған?

- **Терминал эмуляторы**: [iTerm2](https://iterm2.com/)
  - **Тақырыбы (Theme)**: Minimal
  - **Түстер сұлбасы (Color Scheme)**: [Snazzy](https://github.com/sindresorhus/iterm2-snazzy)
  - **Қаріп (Font)**: [FiraCode Nerd Font](https://www.nerdfonts.com/font-downloads)
- **Қабықша (Shell)**: [Fish Shell](https://fishshell.com/)
  - **Конфигурациясы**: [matchai's Dotfiles](https://github.com/matchai/dotfiles/blob/b6c6a701d0af8d145a8370288c00bb9f0648b5c2/.config/fish/config.fish)
  - **Промпт**: [Starship](https://starship.rs/)

## Демо GIF-те көрсетілгендей командаларды автоматты толықтыруды (autocomplete) қалай қосуға болады?

Командаларды толықтыру немесе автотолтыру мүмкіндігін сіз таңдаған қабықша (shell) қамтамасыз етеді. Демо жазбасы [Fish Shell](https://fishshell.com/) қабықшасында жасалған, ол әдепкі бойынша автотолтыруды ұсынады. Егер Z Shell (zsh) қолдансаңыз, [zsh-autosuggestions](https://github.com/zsh-users/zsh-autosuggestions) плагинін қолданып көруді ұсынамыз.

## Жоғарғы деңгейдегі `format` пен `<module>.disabled` бірдей әрекет жасай ма?

Иә, екеуін де промпттағы модульдерді өшіру үшін қолдануға болады. Дегенмен, егер сіз тек модульдерді өшіргіңіз келсе, келесі себептерге байланысты `<module>.disabled` опциясын қолданған жөн:

- Модульдерді жеке өшіру оларды жоғарғы деңгейдегі `format` ішінен жай алып тастауға қарағанда айқынырақ болады
- Starship жаңартылған кезде жаңадан қосылған модульдер промптыңызға автоматты түрде қосылатын болады

## Құжаттамада Starship барлық қабықшаларға арналған деп жазылған. Неге менің сүйікті қабықшам қолдау таппаған?

Starship архитектурасы іс жүзінде кез келген қабықшаға қолдау қосуға мүмкіндік беретіндей жасалған. Starship орындалатын файлы күйсіз (stateless) және қабықшаға тәуелсіз, сондықтан қабықшаңыз промптты баптауды және кеңейтуді (shell expansion) қолдаса, Starship-ті пайдалануға болады.

Мінекей, Starship-ті bash-пен жұмыс істетудің қарапайым мысалы:

```sh
# Соңғы орындалған пәрменнің күй кодын алу
STATUS=$?

# Орындалып жатқан фондық тапсырмалар санын алу
NUM_JOBS=$(jobs -p | wc -l)

# Промпт мәнін `starship prompt` нәтижесіне теңестіру
PS1="$(starship prompt --status=$STATUS --jobs=$NUM_JOBS)"
```

Starship құрамындағы [Bash интеграциясы](https://github.com/starship/starship/blob/main/src/init/starship.bash) сәл күрделірек жасалған, өйткені ол [Команда ұзақтығы модулі (Command Duration)](https://starship.rs/kk-KZ/config/#command-duration) сияқты кеңейтілген мүмкіндіктерді қамтамасыз етеді және алдын ала орнатылған Bash баптауларымен толық үйлесімділікке кепілдік береді.

`starship prompt` қабылдайтын барлық жалаушалар тізімін көру үшін келесі пәрменді іске қосыңыз:

```sh
starship prompt --help
```

Промпт берілген контекст көлеміне қарай жұмыс істейді, бірақ ешбір жалаушаны беру «міндетті» емес.

## glibc-тің ескі нұсқалары бар Linux дистрибутивтерінде Starship-ті қалай іске қосуға болады?

Егер дайын екілік файлды қолданған кезде (мысалы, CentOS 6 немесе 7 жүйелерінде) "_version 'GLIBC_2.18' not found (required by starship)_" қатесі шықса, `glibc` орнына `musl` кітапханасымен жинақталған нұсқасын пайдалануға болады:

```sh
curl -sS https://starship.rs/install.sh | sh -s -- --platform unknown-linux-musl
```

## Неліктен `Executing command "..." timed out.` ескертулерін көремін?

Starship промптта көрсетілетін ақпаратты жинау үшін әртүрлі командаларды орындайды (мысалы, бағдарлама нұсқасы немесе ағымдағы git күйі). Осы командаларды орындау кезінде Starship қатып қалмауы үшін біз уақыт шектеуін орнаттық; егер команда осы уақыттан ұзақ орындалса, Starship оның орындалуын тоқтатып, жоғарыдағы ескертуді шығарады — бұл күтілетін дұрыс мінез-құлық. Бұл уақыт шектеуін [`command_timeout` кілті](../config/#prompt) арқылы реттеуге болады, қаласаңыз уақыт шегін арттыра аласыз. Сондай-ақ төмендегі дебаг қадамдарын орындап, қай команданың баяу орындалып жатқанын анықтап, оны оңтайландыруға тырыссаңыз болады. Соңында, бұл ескертулерді жасыру үшін `STARSHIP_LOG` орта айнымалысын `error` деп орнатуға болады.

## Мен түсінбейтін немесе күтпеген таңбаларды көріп тұрмын, олар нені білдіреді?

Егер сізге бейтаныс белгішелерді көрсеңіз, қазіргі уақытта шығып тұрған модульдердің мәнін түсіндіру үшін `starship explain` командасын қолдана аласыз.

## Starship күтпеген әрекет жасап жатыр, оны қалай тексеруге (debug) болады?

Дебаг журналдарын `STARSHIP_LOG` орта айнымалысын пайдаланып қосуға болады. Бұл жазбалар өте көлемді болуы мүмкін, сондықтан егер сіз нақты бір модульді тексергіңіз келсе (мысалы, `rust` модулін), `module` командасын пайдаланған өте ыңғайлы:

```sh
env STARSHIP_LOG=trace starship module rust
```

Егер starship баяу жұмыс істеп жатса, қандай да бір модуль немесе команда кідіріс тудырып жатқанын анықтау үшін `timings` командасын қолданып көріңіз:

```sh
env STARSHIP_LOG=trace starship timings
```

Бұл команда trace журналын және орындалуына 1 миллисекундтан көп уақыт кеткен немесе нәтиже шығарған барлық модульдердің толық талдауын көрсетеді.

Егер қате тапсаңыз, GitHub-та мәселе (issue) ашу үшін `bug-report` командасын қолданыңыз:

```sh
starship bug-report
```

## Неге менің промптымда арнайы белгішелер (glyph) көрінбейді?

Бұл көбінесе жүйенің дұрыс бапталмауынан болады. Әсіресе кейбір Linux дистрибутивтерінде қаріптер қораптан тыс толық орнатылмаған болуы мүмкін. Төмендегілерді тексеруіңіз керек:

- Жүйелік локаліңіз UTF-8 мәніне орнатылған болуы керек (мысалы, `kk_KZ.UTF-8`, `en_US.UTF-8` немесе `ru_RU.UTF-8`). Егер `LC_ALL` мәні UTF-8 болмаса, [оны өзгерту қажет болады](https://www.tecmint.com/set-system-locales-in-linux/).
- Жүйеде эмодзи қарпі орнатылған болуы керек. Көптеген жүйелерде ол әдепкіде бар, бірақ кейбіреулерінде (мысалы, Arch Linux) болмауы мүмкін. Әдетте оны жүйелік пакет менеджері арқылы орнатуға болады — танымал таңдау: [noto emoji](https://www.google.com/get/noto/help/emoji/).
- Сіз [Nerd Font](https://www.nerdfonts.com/) қарпін пайдаланып жатқаныңызға көз жеткізіңіз.

Жүйені тексеру үшін терминалда келесі пәрмендерді орындаңыз:

```sh
echo -e "\xf0\x9f\x90\x8d"
echo -e "\xee\x82\xa0"
```

Бірінші жол [жылан эмодзиін (🐍)](https://emojipedia.org/snake/), ал екіншісі [powerline branch таңбасын (e0a0)](https://github.com/ryanoasis/powerline-extra-symbols#glyphs) көрсетуі керек.

Егер бұл таңбалар дұрыс көрінбесе, жүйе баптаулары толық емес. Қаріптерді дұрыс баптау кейде күрделі болуы мүмкін. Біздің Discord қолданушылары көмектесе алады. Егер екі таңба да дұрыс көрінсе, бірақ олар starship ішінде әлі де шықпаса, [қате туралы есеп (bug report) қалдырыңыз!](https://github.com/starship/starship/issues/new/choose)

## Starship-ті қалай өшіруге (жоюға) болады?

Starship-ті жою оны орнату сияқты өте оңай:

1. Қабықшаңыздың конфигурациялық файлынан (мысалы, `~/.bashrc`) Starship-ті инициализациялайтын жолдарды алып тастаңыз.
1. Starship орындалатын файлын жойыңыз.

Егер Starship пакет менеджері арқылы орнатылған болса, жою үшін солардың ресми құжаттамасын қараңыз.

Егер Starship ресми орнату скрипті арқылы орнатылған болса, келесі пәрмен орындалатын файлды өшіреді:

```sh
# starship орындалатын файлын тауып өшіру
sh -c 'rm "$(command -v 'starship')"'
```

## Starship-ті `sudo` құқығынсыз қалай орнатуға болады?

Қабықшаның орнату скрипті (`https://starship.rs/install.sh`) тек мақсатты орнату каталогына ағымдағы қолданушының жазу құқығы болмаған жағдайда ғана `sudo` сұрайды. Әдепкі орнату каталогы — `$BIN_DIR` орта айнымалысының мәні немесе `$BIN_DIR` орнатылмаған болса `/usr/local/bin` болады. Егер орнату каталогын өз пайдаланушыңызға жазуға болатын каталогқа ауыстырсаңыз, Starship-ті `sudo`-сыз орната аласыз. Мысалы, `curl -sS https://starship.rs/install.sh | sh -s -- -b ~/.local/bin` пәрмені орнату каталогын `~/.local/bin` етіп орнату үшін скрипттің `-b` опциясын қолданады.

Starship-ті интерактивті емес режимде орнату үшін растауды өткізіп жіберетін `-y` опциясын қосуды ұмытпаңыз. Барлық қолдау көрсетілетін параметрлер үшін орнату скриптінің бастапқы кодын қараңыз.

Пакет менеджерін қолданған кезде, `sudo` арқылы немесе `sudo`-сыз орнату туралы пакет менеджеріңіздің құжаттамасынан қараңыз.
